# 安全模型

远程接入把本机 WebUI 暴露到公网，必须说清楚「谁挡在前面」和「挡不住什么」。本文只描述 v1 的实际边界，不宣称超出实现的能力。

# 三条不可让渡的边界

1. **凭证只存在本机**。设备凭证的明文只在配对响应里出现一次，落盘的是 SHA-256 摘要；状态文件权限 `0600`。
2. **每个请求都实时校验**。没有凭证缓存，撤销后同一个凭证的下一个请求就会被拒。
3. **远端看不到管理页**。`/__anywhere/` 前缀在网关里直接 404，只有 loopback 能访问。

# 威胁模型

| 对手 | 能否得手 | 依据 |
| --- | --- | --- |
| 扫到地址的路人 | 否 | 入口需要 `__Host-dshanywhere` 凭证，没有就只看到 401 提示页 |
| 拿到配对链接的人 | 10 分钟内可 | 链接一次性、单条有效；用掉即失效 |
| 链接泄露后的窗口期 | 可在编辑页内止损 | 「轮换」立即作废未用链接，「撤销」立即断开单台设备 |
| 中转提供方 | **能看到明文** | TLS 在 Worker 处终止，转发的是解密后的内容 |
| Cloudflare 本身 | **能看到明文** | 同上，这是平台能力的固有边界 |
| 拿到本机文件的人 | 能拿到摘要，但不能反推凭证 | 只存 SHA-256；不过他可以直接改状态文件，所以本机访问权限本身是信任根 |

**不防御的边界**：能读本机文件的人、能改本机状态的人、能装 rootkit 的人。这类对手面前任何本地防护都不成立。

# 关于端到端加密

**v1 明确不含端到端加密。** 中转方在技术上可以看到经过它的流量内容。

这不是疏漏，而是有意的取舍：

- 目标使用者自行部署中转，中转运营者就是使用者自己；
- 上 E2E 需要在浏览器里跑一套与宿主会话无关的握手，还得解决静态资源与 WebSocket 帧的双向加解密，复杂度与失败面都远超 v1 的收益；
- 若某天需要跨信任域共享中转，E2E 是必须补的能力，届时会作为独立的 Feature 立项。

在此之前，请把中转当作「你自己家的前门」，而不是「第三方的黑盒代理」。

# 密钥与凭证

| 材料 | 长度 | 存储形式 | 轮换方式 |
| --- | --- | --- | --- |
| 配对链接令牌 | 32 字节随机 | 只存 SHA-256 | 每次生成新链接即作废旧链接 |
| 设备凭证 | 32 字节随机 | 只存 SHA-256 | 撤销设备后重新配对 |
| 宿主会话 cookie | 由 DSH 生成 | 插件内存缓存 ≤ 10 分钟 | 收到 401 时强制换发 |

设备上限 10 台；超过上限的新配对会被拒绝。撤销记录保留在状态文件里用于审计。

# 轮换与撤销

两者都在桌面端「远程接入」页面完成，1 分钟内生效（实际上是立即生效）：

- **轮换链接**：`POST /__anywhere/api/rotate`。递增 `linkEpoch`、作废所有未使用链接，**不动设备表**。已配对设备继续可用。
- **撤销单台设备**：`POST /__anywhere/api/devices/:id/revoke`。把设备置为 `revoked` 并立即移出查表。撤销最后一台时会返回 `no-active-device`，界面要求二次确认。
- **整体关闭**：`POST /__anywhere/api/disable`。断开隧道并拒绝新配对，已配对设备访问得 503。

# 日志与脱敏

日志里不出现令牌明文：

- URL 中的 `/p/<token>` 段被替换为 `[已隐去]`；
- `cookie`、`authorization` 一类请求头整体替换；
- 错误页与状态 API 的响应体都不含凭证或摘要（有单测守着，见 `tests/unit/redact.test.ts`）。

# 传输安全

- 浏览器 ↔ 中转：HTTPS/WSS（Cloudflare 提供证书）；
- 中转 ↔ 电脑：出站 WSS，不需要开放入站端口、不需要公网 IP；
- 电脑 ↔ DSH：只走 `127.0.0.1`，Host/Origin/Referer 在转发时被改写到 loopback；
- 上游 `Set-Cookie` 一律丢弃，loopback 会话 cookie 不会回流给浏览器。
