# 快速验证指南：DSHAnywhere 端到端验收

**Feature**: `001-browser-remote-access` | **日期**: 2026-11-04

本文件是**验收脚本**，不是实现说明。每个场景对应 spec 的成功标准或功能需求，执行后把结果填进最后的记录表。实现细节见 [plan.md](plan.md) 与 [contracts/](contracts/)。

## 0. 前置条件

| 项 | 要求 |
| --- | --- |
| 机器 A（桌面） | 装有 DSH 桌面版，应用可启动并常驻托盘；Node ≥ 22（用于 `npx`）；可访问 `https://workers.dev` |
| 机器 B（远端） | 手机或另一台电脑的现代浏览器；**不得**安装任何客户端 |
| Cloudflare 账号 | 使用者自己的账号（Free 计划） |
| 网络 | 机器 B 不在机器 A 的局域网内（或至少用蜂窝网络验证） |

自检：

```bash
node --version            # ≥ 22
npx --version             # 能联网拉包
dsh --version             # DSH CLI 可用
```

## 场景 1：从零建立中转（SC-001，目标 ≤ 10 分钟）

1. 打开计时器，清零。
2. 执行仓库提供的唯一部署命令（见 `docs/relay-setup.md`）：

   ```bash
   npx wrangler deploy --config relay/wrangler.toml
   ```

3. 按提示完成账号授权（浏览器一次），记录得到的 `https://<name>.<account>.workers.dev`。
4. 访问 `https://<name>.<account>.workers.dev/__relay/health`。

**期望**：返回 `{"ok":true,"protocolVersion":1,"agent":"absent"}`。

**记录**：部署耗时 ______ 分钟。

## 场景 2：装插件并接入（SC-001 续，SC-008）

1. 安装插件（两条命令，见 `docs/install.md`）。
2. 重启桌面应用，打开本地管理页 `http://127.0.0.1:<port>/__anywhere/`。
3. 填入场景 1 的地址，保存。

**期望**：
- 状态从「未配置」→「连接中」→「已连接」，≤ 2 秒；
- 页面显示固定入口地址与二维码；
- 未安装任何除插件外的软件。

**记录**：累计耗时 ______ 分钟（目标：与场景 1 合计 ≤ 10）。

## 场景 3：首次配对与 10 分钟有效期（FR-004/FR-005，澄清 1）

1. 点「生成配对链接」，手机扫码（或手输地址）。
2. **期望**：浏览器跳转到 `https://<relay>/`，地址栏不含令牌；界面可见。
3. 再次生成新链接，等 11 分钟后再用旧链接访问。
4. **期望**：401 提示「链接无效或已过期：请在电脑端重新生成配对链接」；同一提示也出现在"已使用一次"与"已轮换"的情况下（三者文案必须一致）。

## 场景 4：远程看见并驱动（FR-009~FR-012，SC-007）

1. 在机器 A 启动一个会持续输出的长任务。
2. 机器 B 上观察：输出持续到达，无卡顿、无重复。
3. 在机器 B 提交一条指令 → 机器 A 与机器 B 同时看到相同过程。
4. 触发一个需要应答的交互（如审批）→ 在机器 B 应答 → 会话继续；机器 A 无需重复操作。
5. 在机器 B 执行一个会写文件的操作 → 到机器 A 检查产物。

**期望**：四步结果与在机器 A 本地操作完全一致；机器 B 上看不到任何"只读""受限"提示。

## 场景 5：日常零操作（FR-006，SC-002/SC-004）

1. 关闭机器 B 的全部页面，重启浏览器，直接打开 `https://<relay>/`。
2. **期望**：无需任何操作直接进入。
3. 连续 5 天重复，记录是否需要重新配对。

**期望**：5/5 免操作；重复配对 0 次。

## 场景 6：断线恢复（FR-023，SC-003）

| 子场景 | 操作 | 期望 |
| --- | --- | --- |
| 6a 网络切换 | 手机 Wi-Fi ⇄ 蜂窝 | ≤ 30 秒恢复，无需刷新以外的操作 |
| 6b 中转重启 | `npx wrangler deploy` 重新部署一次 | ≤ 30 秒恢复，重新握手 |
| 6c 短时断网 | 关闭手机网络 20 秒再恢复 | 自动恢复 |
| 6d 桌面端重启 | 退出并重开桌面应用 | 恢复；期间浏览器显示明确提示 |

## 场景 7：止损（FR-015~FR-019，SC-006）

1. 在机器 B 保持一个已配对会话。
2. 机器 A 管理页点「轮换」。
3. **期望（≤ 60 秒内）**：新链接立即失效；机器 B 的既有会话**不受影响**。
4. 机器 A 点撤销机器 B 的设备。
5. **期望**：机器 B 的下一次请求被拒绝（401），需重新配对才能恢复。
6. 检查插件日志与中转日志（`wrangler tail`）：**不得**出现任何令牌或 cookie 明文。

## 场景 8：故障可区分（FR-013）

| 制造的情况 | 在哪看 | 期望文案 |
| --- | --- | --- |
| 退出桌面应用 | 远端浏览器 | 「电脑端未运行…」 |
| 断网 20 秒后恢复 | 远端浏览器 | 「连接已中断…」随后自动恢复 |
| 停用中转（控制台禁用 Worker） | **桌面端状态页** | 「中转不可达…」 |
| 人为耗尽额度（或用 `wrangler dev` 模拟） | **桌面端状态页** | 「中转额度已用尽或被限制…」 |
| 用失效链接访问 | 远端浏览器 | 「链接无效或已过期…」 |

**要求**：五类互不相同、均无堆栈、均无内部路径；后两类只要求在桌面端状态页呈现——中转不在线时没有任何服务方能返回我们的页面。

## 场景 9：零安装与作者零基础设施审计（SC-008/SC-009）

1. 在机器 B 的浏览器开发者工具里记录全部网络请求域名。
2. **期望**：只有 `https://<name>.<account>.workers.dev`（以及浏览器自身的更新检查）。
3. 全仓检索作者端点：

   ```bash
   grep -rn "workers.dev\|https://" packages/ --include=*.ts --include=*.toml | grep -v "example"
   ```

   **期望**：无硬编码的作者域名、账号或 Token；仅有注释/文档中的示例占位。

## 场景 10：可访问率与并发（SC-005/SC-010）

1. 一次"离家会话"中做 40 次访问（含打开、刷新、切后台再回前台），记录失败次数。
2. **期望**：成功率 ≥ 95%，且数字可在管理页统计中看到。
3. 同时用 2 台设备（手机 + 平板）访问同一会话 5 分钟。
4. **期望**：互不中断，双方都能提交指令。

## 已知的 POC 前置项

以下三项必须在场景 1~4 之前用最小脚本先验证，否则后面的场景可能整批失败：

1. **额度与消息边界**：真实会话一轮的输出密度、单次响应体量（对应 research.md R1/R5）。
2. **代理下资源路径**：首屏 HTML/JS 中是否存在指向 `127.0.0.1:<port>` 的绝对 URL（R7）。
3. **安装步骤计时**：两条安装命令是否真的能把总时间压在 10 分钟内（R10）。
