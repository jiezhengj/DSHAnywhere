# Feature Specification: DSHAnywhere 浏览器远程接入

**Feature Branch**: `001-browser-remote-access`

**Created**: 2026-11-04

**Status**: Draft

**Input**: 用户描述 + `.specify/assessments/dsh-anywhere/decision.md` 的 go 结论与交接摘要

## 概述

桌面版 DeepSeek Harness 只在回环地址上提供 WebUI，人离开电脑就失去对正在运行的长任务的可见性与干预能力。本功能为桌面端增加一个可选的远程入口：使用者用自己的 Cloudflare Worker 作为中转，浏览器经该固定地址访问到桌面端同一套原生 WebUI，首次扫码配对后长期免操作；PC 端可随时轮换凭证与撤销设备。远程看到和能做的事与坐在电脑前完全一致——不改变 DSH 的任何行为。

## 澄清记录（Clarifications）

### Session 2026-11-04

- Q: 一次性配对链接在还没被扫过之前，应该一直有效，还是有一个固定有效期？ → A: 固定有效期 10 分钟，过期即失效，桌面端可随时重新生成。
- Q: 首屏可见时延是否需要设定硬性上限？ → A: 不设硬阈值。该时延主要由使用者网络与中转连通性决定，插件侧只有常驻通道、静态资源缓存等实现级手段；由 POC 实测基线记入 plan，作为后续回归参照，不在规格中预设数值。

## 用户场景与测试（User Scenarios & Testing）

用户故事按独立可分片的优先级排列：每个故事单独实现都能交付可用价值，优先执行 P1。

### 用户故事 1 — 离开电脑后仍能看见并驱动正在进行的长任务（优先级：P1）

用户在家用桌面上启动了一个要跑很久的任务，然后出门。在手机上他打开早已保存的固定网址，看到同一个桌面会话正在流式输出；他在浏览器里补一句指令，会话照常继续；需要他应答的交互请求也在浏览器里出现并可作答。整个过程与坐在电脑前操作没有区别。

**为什么是这个优先级**：这是本功能的唯一核心价值，没有它其余部分都不成立；其余故事只是在降低摩擦和控制风险。

**独立测试**：在一台电脑上运行桌面端并启动一个持续输出的任务；从另一台设备的浏览器访问已建立的入口，确认输出持续到达；提交一条指令，确认会话按该指令继续且桌面端与远端状态一致。仅此一项即可交付 MVP 价值。

**验收场景**：

1. **给定** 桌面端正在运行一个持续输出的会话且远程入口已建立，**当** 用户从外部浏览器打开入口地址，**则** 浏览器在数秒内显示该会话当前内容并持续接收新增输出。
2. **给定** 浏览器已显示该会话，**当** 用户输入一条指令并提交，**则** 会话在桌面端与远端同时继续，远端看到的执行过程与本地一致。
3. **给定** 会话发起需要用户应答的交互请求（例如审批），**当** 用户在远端应答，**则** 会话按该应答继续，桌面端无需重复操作。
4. **给定** 用户在远端执行一个会改变工作区或产出文件的操作，**当** 操作完成，**则** 结果与在本地执行同一操作完全一致，权限档位不变。

### 用户故事 2 — 从零到可用不超过 10 分钟（优先级：P2）

用户按一页文档把自己的中转部署好（一条命令），把中转地址填进插件，桌面端随即显示固定网址与一次性二维码；他用手机扫一次码就进入了界面。全程不安装额外客户端、不买域名、不配置 DNS。

**为什么是这个优先级**：首次可用时间是这类工具最容易被劝退的环节，也是既定成功指标之一；它决定核心价值能否被人真正体验到。

**独立测试**：从"尚未安装插件"开始计时，只允许读文档、执行一条部署命令、在插件里填写一次中转地址、扫一次码，直到手机浏览器显示会话界面；记录耗时，并核对过程中除插件外没有安装任何软件。

**验收场景**：

1. **给定** 使用者拥有可用于部署中转的服务账号且尚未部署，**当** 按文档执行提供的部署命令，**则** 得到一个可用的固定 HTTPS 入口地址。
2. **给定** 中转已部署，**当** 用户在桌面端填入中转地址，**则** 桌面端在数秒内显示入口地址与一次性二维码。
3. **给定** 桌面端已显示二维码，**当** 用户用手机浏览器扫码打开，**则** 浏览器完成配对并跳转到不含凭证的干净地址，界面可用。
4. **给定** 用户没有自己的域名，**当** 完成上述流程，**则** 入口地址仍为 HTTPS 且长期固定，无需购买域名或配置解析。
5. **给定** 桌面端已显示二维码，**当** 用户超过 10 分钟才扫码，**则** 该链接已失效并提示到电脑端重新生成；重新生成后可在 10 分钟内完成配对。

### 用户故事 3 — 日常零操作复用固定地址（优先级：P3）

第二天再出门，用户直接打开上次保存的那个网址，不做任何操作就回到了界面；不需要重新扫码、不需要重新获取地址、不需要启动任何额外程序。

**为什么是这个优先级**：它是"日常零操作"这一成功指标的直接载体；如果每次都要重新配对，核心价值会被操作成本抵消。

**独立测试**：在已配对状态下关闭全部浏览器页面，重新打开同一地址，确认无需任何额外操作直接进入；连续多日重复验证。

**验收场景**：

1. **给定** 设备已完成配对且桌面端在后台运行，**当** 用户重新打开入口地址，**则** 直接进入界面，不出现配对或登录步骤。
2. **给定** 用户使用了隐私浏览或清除了浏览器数据，**当** 再次打开入口地址，**则** 系统明确提示需要重新配对，而不是显示难以理解的错误。
3. **给定** 设备已配对超过一个月但期间有过正常访问，**当** 用户再次打开入口地址，**则** 仍然免操作进入，无需重新配对。

### 用户故事 4 — 链接泄露时的止损（优先级：P4）

用户怀疑自己发出的链接被转发到了群里。他在桌面端点一下"轮换"，旧能力链接立刻失效；又在设备列表里发现一台不认识的设备，点"撤销"，那台设备立即无法访问。全程不到一分钟，不需要命令行。

**为什么是这个优先级**：在"不做密码/TOTP"的安全模型下，轮换与撤销是泄露后唯一的止损手段，属首版必备；但它不是日常路径，因此排在核心体验之后。

**独立测试**：先用一条能力链接或一台已配对设备确认访问可用；在桌面端执行轮换/撤销，确认同一链接或设备在 1 分钟内被拒绝，而其它已配对设备不受影响。

**验收场景**：

1. **给定** 一条尚未使用的能力链接，**当** 用户执行密钥轮换，**则** 该链接立即失效，未撤销的已配对设备仍可正常访问。
2. **给定** 设备列表中存在某台设备，**当** 用户撤销该设备，**则** 该设备的下一次访问被拒绝，状态视图立即反映该结果。
3. **给定** 某设备已被撤销，**当** 该设备再次尝试访问，**则** 必须由用户重新完成配对授权才能恢复，不能凭旧凭证自动回到会话。
4. **给定** 任意无效或已撤销的凭证，**当** 有人访问入口，**则** 一律被拒绝，且响应不泄露内部结构、DSH 细节或凭证是否存在。

### 用户故事 5 — 连接状态可见、断线自愈（优先级：P5）

中转重启或手机换了网络后，用户不需要做任何事：几十秒内界面自行恢复。如果电脑端已经退出，浏览器上看到的是明确的中文提示，而不是白屏或错误堆栈。

**为什么是这个优先级**：可访问率与断线恢复时间都是既定指标，且"不知道出了什么问题"会让使用者放弃该工具；它决定长期可用性，但不改变核心交互。

**独立测试**：在使用过程中分别重启中转、切换手机网络、让电脑短暂休眠、关闭桌面端，确认恢复时间、提示文案与状态视图表现符合预期。

**验收场景**：

1. **给定** 正在使用中，**当** 手机在蜂窝与 Wi-Fi 之间切换，**则** 界面在 30 秒内自行恢复，无需用户做除等待之外的操作。
2. **给定** 正在使用中，**当** 中转被重启或重新部署，**则** 桌面端自动重新连接，浏览器恢复可用。
3. **给定** 桌面端已退出或电脑已关机，**当** 用户打开入口地址，**则** 显示"电脑端未运行"这一类明确提示。
4. **给定** 中转额度耗尽或被平台限制，**当** 用户访问，**则** 看到可定位原因的提示，而不是静默失败。
5. **给定** 用户打开状态视图，**则** 能看到中转连接状态、当前入口地址、配对二维码、已配对设备列表与各设备最近访问时间。

### 边界情况

- 同一入口被两台以上已配对设备同时使用，互不中断。
- 二维码或能力链接被截图、转发后被第三方抢先使用（视为已泄露，靠轮换与撤销止损）。
- 会话进行中电脑进入睡眠或合盖，随后唤醒；唤醒后是否需要用户操作、恢复时间是否落在 30 秒内。
- 用户在中转侧重新部署导致地址变化（v1 假定地址固定；地址变化时须能让用户重新填入并恢复）。
- 单次输出体积很大（长代码段、大段日志、附件内容）时仍然可用；超出中转限制时明确失败并可重试，不得表现为界面卡死。
- 浏览器页面长时间停留（跨天）后恢复交互。
- 桌面端升级到不兼容版本后重启，远程入口的表现。
- 用户在中转控制台直接删除或停用中转。
- 移动设备在后台被系统挂起后回到前台。
- 系统时间明显偏差时对凭证有效性的判断（倾向拒绝而非误放行）。
- 能力链接超过 10 分钟未被使用而失效后，用户再次扫码或打开该链接。

## 需求（Requirements）

### 功能需求

**接入与配对**

- **FR-001** 系统必须（MUST）在桌面端提供一处入口，集中给出建立中转所需的全部信息（文档位置、完整命令、成功后的下一步），使用者不必阅读源码或自行拼装步骤。
- **FR-002** 使用者必须只需在桌面端填写一个中转地址即可完成接入，不得要求编辑配置文件或使用命令行。
- **FR-003** 接入后系统必须提供一个固定的公网 HTTPS 入口地址，且不要求使用者拥有域名或配置 DNS。
- **FR-004** 系统必须能按需生成一次性能力链接（高熵、不可枚举），并在桌面端以二维码与可复制文本两种形式呈现；链接自生成起 10 分钟内有效，超时或已被使用即失效；失效后再次访问必须给出"链接无效或已过期，请在电脑端重新生成"一类可操作提示，且提示措辞必须统一，不区分该凭证从未存在、已过期还是已被撤销。
- **FR-005** 使用者用任意现代浏览器打开能力链接后，系统必须完成配对、下发长期凭证，并跳转到一个不含凭证的干净地址。
- **FR-006** 配对完成后，同一浏览器再次打开入口地址必须无需任何操作直接进入。
- **FR-007** 同一台电脑必须支持配对多台浏览器设备并存，多台设备必须能同时访问。
- **FR-008** 每台设备必须有独立标识，可在桌面端单独撤销。

**远程使用**

- **FR-009** 远端必须能看到会话的实时进展，观感与本地一致（流式输出、交互请求、状态变化）。
- **FR-010** 远端必须能与本地等价地驱动会话：发送输入、应答交互请求、执行与本地相同的操作。
- **FR-011** 远端的能力与限制必须与本地完全相同，不得引入只读观察模式、权限降级或任何 DSH 原生不存在的模式。
- **FR-012** 系统不得改变 DSH 的权限模型、会话状态语义或原生界面行为。
- **FR-013** 入口在任何不可用状态下都必须给出可理解、可区分的提示，不得白屏、无提示超时或暴露错误堆栈；至少区分"电脑端未运行""中转不可达""中转被平台限制或额度耗尽"三种情况。
- **FR-014** 会话必须留在桌面端现有进程中运行；系统不得另起会话宿主去接管同一会话。

**安全与止损**

- **FR-015** 能力链接与设备凭证必须为高熵随机值，不得出现在日志、错误信息或任何外发内容中。
- **FR-016** 桌面端必须提供密钥轮换；执行后旧能力链接立即失效，未撤销的已配对设备继续可用。
- **FR-017** 桌面端必须提供单设备撤销；执行后该设备的访问立即被拒绝。
- **FR-018** 轮换与撤销必须通过界面完成（不依赖命令行），且必须在 1 分钟内生效。
- **FR-019** 任何无效、过期或已撤销的凭证必须一律拒绝，且响应不得泄露内部结构、DSH 细节或凭证是否存在。
- **FR-020** 传输必须全程加密；浏览器侧凭证必须不可被页面脚本读取、不随跨站请求发送；响应必须避免通过来源信息泄露地址。
- **FR-021** 中转不得记录请求正文、凭证或会话内容。

**状态与可观测**

- **FR-022** 桌面端必须提供状态视图，展示：中转连接状态、当前入口地址、配对二维码、已配对设备列表及各设备最近访问时间。
- **FR-023** 断开后系统必须自动恢复连接，恢复过程不得要求用户操作。
- **FR-024** 系统必须记录足以计算"可访问率"的访问结果（成功/失败次数或最近成功时间），并可在状态视图或中转侧日志中查看。

**运维与兼容**

- **FR-025** 建立中转必须是"文档 + 一条命令"的形态；v1 不得提供内置部署向导、API Token 流程或中转自动升级。
- **FR-026** v1 必须只支持一种中转类型；其它中转（VPS、NAS）必须在文档中明确标注为暂不支持，且不得出现半实现。
- **FR-027** 桌面端版本不兼容时必须禁用远程入口并给出明确的升级/降级指引，不得静默降级或呈现"半可用"状态。
- **FR-028** 连接协议必须预留安装 ID 字段；v1 必须只支持"一台中转对应一台电脑"，不得表现为支持多台电脑。

### 关键实体

- **中转（Relay）**：使用者自建的公网入口，提供固定地址；由使用者部署与维护，与一台电脑绑定。关键信息：地址、连接状态、最后连接时间。
- **安装（Installation）**：桌面端的一次插件安装实例，拥有唯一安装 ID；v1 中一个安装只对应一台电脑与一台中转。
- **设备（Device）**：一台已配对的浏览器。关键信息：标识、可辨识的名称或来源提示、配对时间、最近访问时间、状态（有效/已撤销）。
- **能力链接（Capability Link）**：一次性配对用的高熵链接，生成后 10 分钟内有效，使用后即被消费。
- **设备凭证（Device Credential）**：配对后浏览器持有的长期凭证，后续访问自动携带；可按设备单独撤销。
- **连接（Connection）**：桌面端到中转的会话连接。状态：已连接 / 重连中 / 未连接。

## 范围外（Out of Scope）

v1 明确不包含：

- VPS 与 NAS 中转（连接协议预留安装 ID 字段，但功能不实现）。
- 密码、失败锁定、TOTP/多因素、账号体系。
- 只读观察模式、远程权限降级、任何 DSH 原生之外的会话模式。
- 修改 DSH 的权限模型、认证与信任栅栏或会话语义。
- 移动端专用 UI；沿用原生 WebUI，响应式由 DSH 负责。
- 多用户、权限分级、团队共享、审计报表与配额管理。
- 会话历史浏览器、任务编排等 DSH 已有能力。
- 内置部署向导、中转自动升级、作者托管服务、作者提供的域名/服务器/账号/凭据。
- 浏览器端或 PC 端任何额外客户端的安装（含 Tailscale、cloudflared、ngrok 等）。
- 局域网直连、路由器端口映射、DDNS 等不经中转的接入路径。

## 成功标准（Success Criteria）

### 可度量结果

- **SC-001 首次可用时间**：从"开始安装插件"到"手机浏览器首次看到会话界面"≤ 10 分钟，其间除插件外不安装任何软件。
- **SC-002 日常零操作**：配对完成后，"直接打开固定地址即可进入"的比例为 100%（以连续 5 天日常使用抽查为准）。
- **SC-003 断线恢复**：中转重启、网络切换或短时断网后，自动恢复可用 ≤ 30 秒，且无需用户操作。
- **SC-004 重复配对频率**：同一设备在非换机场景的重复配对 ≤ 1 次/月。
- **SC-005 可访问率**：单次离家期间，"远程访问成功次数 / 尝试次数"≥ 95%，且该比例可从状态视图或中转日志统计。
- **SC-006 止损时间**：轮换或撤销后，旧链接与被撤销设备在 ≤ 1 分钟内被拒绝，且其它设备不受影响。
- **SC-007 一致性**：抽查典型操作（提交指令、应答交互、观察流式输出、查看大体积输出），远端结果与本地完全一致，无行为差异。
- **SC-008 零安装**：完成上述全部流程，浏览器端安装 0 个客户端/扩展，PC 端安装 0 个额外程序。
- **SC-009 作者零基础设施**：使用过程中不产生任何指向作者服务器、域名或账号的请求；交付物内不含作者端点或凭据。
- **SC-010 并发设备**：2 台以上已配对设备可同时访问同一会话，互不中断。

## 假设（Assumptions）

- 桌面应用以托盘常驻方式运行，关闭主窗口不终止桌面端进程；电脑保持开机且不休眠。
- 使用者拥有可用于部署中转的云服务账号，并愿意执行一次"文档 + 一条命令"的部署。
- 使用者的中转地址天然公网可达并具备有效 HTTPS；v1 所选的中转形态使这一步不需要使用者购买域名。
- 使用者的中转在免费额度内运行；额度触顶属硬失败，系统需给出可定位提示，但不保证降级可用。
- 浏览器为支持现代 Web 标准（实时双向通信、安全凭证存储）的近期版本，手机与桌面浏览器均适用。
- 长期凭证在有效访问时自动续期，仅在撤销或轮换后失效，不因浏览器关闭或超过固定天数而强制重新配对。
- 密钥轮换只作废"未使用的能力链接"，不强制已配对设备重新配对；"让全部设备失效"由逐台撤销表达。
- 同一台电脑只有一份插件安装与一台中转；多台电脑是后续版本的目标。
- 中转由使用者自行维护；插件不假定中转内部实现，只依赖其对外提供的固定地址。
- 网络条件为移动网络或普通家庭宽带，允许短时断线、网络切换与丢包。
- v1 唯一支持的中转形态是使用者自己的 Cloudflare Worker（免费计划）；VPS 与 NAS 留待后续版本。
- 依赖 DSH 桌面版提供的原生 WebUI 与既有会话机制；插件只做接入，不引入新的会话通道。
- 首屏可见时延不设硬性上限：它主要由使用者网络与中转连通性决定；v1 以 POC 实测基线为准，后续发布不得明显劣化该基线。
