# Problem Definition: 离开电脑后无法看见并驱动桌面会话

- **Slug**: dsh-anywhere
- **创建时间**: 2026-11-04
- **输入来源**: intake.md + research.md

## 问题陈述

当长任务在桌面版 DeepSeek Harness 中运行时，人一旦离开电脑，就同时失去两样东西：对任务进展的可见性，以及在需要时对同一会话的干预能力。现有替代要么要求远程设备安装并运行客户端（如 Tailscale），要么根本无法驱动桌面进程已持有的会话（另起 Web Host 会被单写者租约拒绝），因此该场景目前没有低成本、零安装的解法。

## 受影响的用户与干系人

- **用户（主场景）**：作者本人 — 长任务执行期间离开电脑，需要在手机或外部浏览器上看进展、必要时继续驱动会话。 — [source: intake.md]
- **用户（分发场景）**：自带 Cloudflare Worker / VPS / NAS 之一的同类 DSH 使用者 — 愿意自建中转换取固定地址与零客户端。 — [source: intake.md，约束澄清]
- **干系人**：作者 — 唯一决策者与维护者，决定了"不做作者托管中转"。
- **干系人**：DSH 上游 — 其内部契约变化会影响插件可用性。 — [source: research.md]
- **干系人**：朋友/同类使用者 — 使用插件的人，需要自行准备并维护中转。

## 目标

- 离开电脑后，能用普通浏览器看到桌面会话的实时进展（不需要安装任何客户端）。
- 能在同一会话上继续操作，效果与坐在电脑前一致。
- 地址固定：首次配对后，后续打开同一网址即可进入，不再需要重新获取地址或重复配对。
- 使用者自带中转（Worker / VPS / NAS），作者不承担任何基础设施、账号与运营成本。
- 不要求域名：默认无域名，也能拿到固定 HTTPS 入口。
- 每种中转都有清晰的"建立中转 → 接入 → 首次配对"流程，失败时可定位、可降级。

## 非目标

- 不改动 DSH 的权限模型、不新增会话能力、不改变远程会话的权限档位（与本地完全一致）。
- 不做"只读观察模式"或任何 DSH 原生的额外模式。
- v1 不做密码、失败锁定、TOTP；安全模型为"能力链接 + 长期 cookie"。
- 不提供作者托管的中转、账号、域名或服务器。
- 不做移动端专用 UI（沿用原生 WebUI，响应式由 DSH 负责）。
- 不做多用户、权限分级、团队共享（单用户工具）。
- 不做会话历史浏览器、任务编排等原生已有能力。
- 不改造 DSH 的认证与信任栅栏，只做等价的 loopback 转发。

## 假设与约束

- **已确认的硬约束**（来自会话澄清，2026-11-04）：
  - 浏览器端零安装；
  - PC 端零额外客户端，能力集成在插件内；
  - 默认预设无域名，使用者必然自带 Worker / VPS / NAS 之一并自建中转；
  - 作者不托管任何基础设施；
  - 接入顺序：Worker → VPS → NAS（NAS 需可达性自检）；
  - 目标体验：扫一次、固定地址、长期可用；
  - v1 安全模型为能力链接，**"轮换 + 撤销"是 v1 必备**，不是后续优化。
- **假设**：桌面 App 以托盘常驻方式运行，关闭窗口不终止 Host。
- **假设**：使用者的中转可被公网访问（VPS 有公网 IP，NAS 具备端口映射或厂商远程入口，Worker 天然可达）。

## 成功指标

- **首次可用时间**：从开始安装插件到手机浏览器首次看到界面 ≤ 10 分钟（基线：当前不存在该能力）。
- **日常免操作**：配对完成后，日常使用无需任何额外操作即可打开（基线：现状需要远程桌面或隧道工具）。
- **断线恢复**：中转或网络掉线后自动恢复 ≤ 30 秒（基线：不可用）。
- **重复配对频率**：首次配对后，非换机场景的重复配对 ≤ 1 次/月（基线：不可用）。
- **单次离开期间可访问率**：远程访问成功次数 / 尝试次数 ≥ 95%，由插件状态页或中转日志可观测（基线：不可用）。
- **安全性（定性）**：链接泄露可通过"轮换 + 撤销"在 1 分钟内止损。

## 不作为的代价

长任务期间必须守在电脑旁，或事后才知道结果；出现需要干预的情况时错过窗口；继续依赖远程桌面（重、手机体验差）或 Tailscale（违反零安装约束），导致该场景事实上不可用。
