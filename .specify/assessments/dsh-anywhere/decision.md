# Decision: DSHAnywhere 值不值得投入到 Feature SDD

- **Slug**: dsh-anywhere
- **决定时间**: 2026-11-04
- **结论**: go
- **已审阅产物**: intake.md、research.md、problem.md、concept.md

## 评分卡

| 维度 | 评级 | 依据 |
| --- | --- | --- |
| 问题是否成立 | strong | 触发场景具体且反复出现：长任务跑着时人离开电脑，既看不到也驱动不了；现有替代（远程桌面、Tailscale、`dsh web`）各自被约束否掉，问题真实存在。 |
| 证据强度 | adequate | DSH 内部机制（宿主 web server API、cookie 换发、会话单写者租约、托盘常驻）均有本地源码级证据，置信度高；Worker 额度与 NAS 可达性只有文档/推演，置信度中；需求侧是单用户自述，非广泛调研。 |
| 相对不作为的价值 | strong | 不做的代价是继续守在电脑旁或事后才知道；而唯一同时满足"零安装 + 固定地址 + 驱动桌面会话"的路径就是本方案。 |
| 可行性与工作量 | adequate | 推荐 Option A（Worker 中转直通），工作量周级；rabbit holes 已识别（WS 多路复用与大消息、断线重连、代理下静态资源与注入、cookie/信任栅栏、上游契约变化）。 |
| 战略契合 | adequate | 项目本身即为作者自用工具；与 DSH 插件生态一致。项目 Constitution 尚未正式确立（init 只复制了模板），此项留待 Constitution 阶段确认。 |
| 风险姿态 | adequate | 主要风险已识别并有对应手段：无认证 → 能力链接 + 轮换 + 撤销（v1 必备）；Worker 额度未知 → 早期 POC 验证 + 大流量走 HTTP 旁路；上游契约变化 → 锁定兼容版本并探测。仍存在"平台额度触顶即硬失败"的未消除风险。 |

## 结论与理由

评分卡没有任何一项落到 weak，证据强度达到 adequate，且已有明确推荐的方案选项，因此结论是 **go**——值得进入 Feature SDD 做正式规格。

需要说明的是：**go 只表示"值得继续考虑"**，是否真的实施、投入多少时间由用户决定；本结论不包含任何实施承诺。

两个未知项不构成 go 的阻碍，但应作为实施早期必须验证的条件：

1. Worker Free 计划的 Durable Objects 额度与 WebSocket 帧上限能否承载真实 WebUI 流量（未知，需 POC）；
2. 无认证模型下，"链接泄露 → 轮换 + 撤销"的止损路径必须在首个版本内可用（已确认必备）。

## go —— 交接给 `$speckit-specify`

- **问题**：长任务在桌面版 DSH 中运行时，人离开电脑即失去对同一会话的可见性与干预能力；现有替代要么要求远端安装客户端，要么无法驱动桌面进程持有的会话。
- **选定方案**：Option A — 插件在桌面 Host 内挂网关，主动出站连接使用者自己的 Cloudflare Worker（固定 `*.workers.dev` 地址），浏览器经 Worker 访问到原生 WebUI；首次扫码配对，长期 cookie 生效；PC 端可轮换密钥与撤销设备。
- **范围内**：Worker 中转；单台电脑（插件实例）+ 多台浏览器设备配对；首次配对与长期 cookie；轮换与撤销；状态页（连接状态、地址、二维码、设备列表）；"建立中转"采用文档 + 一条命令的简单形态。
- **范围外**：VPS/NAS 中转（协议预留安装 ID 字段）、密码/失败锁定/TOTP、只读观察模式、改 DSH 权限模型或认证栅栏、移动端专用 UI、多用户与权限分级、会话历史浏览、内置部署向导、中转自动升级。
- **成功指标**：首次可用 ≤ 10 分钟；日常零操作；断线恢复 ≤ 30 秒；非换机重复配对 ≤ 1 次/月；单次离开可访问率 ≥ 95%；链接泄露 1 分钟内可止损。
- **随行的待澄清问题**：
  - Worker Free 额度与 WS 帧上限的实际边界（POC 验证）。
  - 原生 WebUI 在代理路径下的静态资源与 index 注入是否正常工作。
  - 插件对 DSH 桌面版本的兼容策略（锁版本 / 探测失败即禁用 / 提示升级）。
  - 一个中转是否将来要支持多台电脑（v1 预留字段）。
